## 1. Overview

This feature implements the core configuration loading logic for the SpecTRAC agent. It must reliably locate, parse, and merge settings from the two primary configuration sources: the **Solution Manifest** (`spectrac.tsln`) and the **Project Manifest** (`{project}.tproj`), ensuring project-level settings override solution-level defaults where specified in `commands.md`.

## 2. Requirements (EARS)

### R-P0-001: Configuration Discovery
WHEN the SpecTRAC agent is initialized from the repository root,
THE SYSTEM SHALL check for the existence of `spectrac.tsln` in the root folder to determine if the environment is a **Solution Context**.
**Acceptance Criteria:**
* If `spectrac.tsln` exists, the agent MUST transition to **Solution Context Mode**.
* If `spectrac.tsln` does not exist, the agent MUST assume **Single Project Mode** and search for a single `*.tproj` file in the root's `.spectrac/` directory.

### R-P0-002: Manifest Parsing
WHEN a manifest file (`.tsln` or `.tproj`) is located,
THE SYSTEM SHALL parse the file contents using **PyYAML** into a Python dictionary, strictly adhering to the YAML format.
**Acceptance Criteria:**
* Parsing MUST successfully handle mandatory fields (`solution.id`, `project.id`, `projects[]`, etc.) without error.
* Validation MUST be performed against a defined **Pydantic Schema** (P-001-F-002, Task T-003).

### R-P0-003: Solution Context Loading
WHEN operating in **Solution Context Mode**,
THE SYSTEM SHALL load and validate `spectrac.tsln`, then enumerate all project paths listed in the `projects[]` array.
**Acceptance Criteria:**
* For each entry in `projects[]`, the system MUST record the `project.id`, `project.name`, and the relative `path` to the project's folder.
* The agent MUST defer loading the specific Project Manifest (`.tproj`) until the target project is selected by the user (as per `commands.md`).

### R-P0-004: Configuration Merging and Overrides
WHEN a Project Manifest (`.tproj`) is loaded in either mode,
THE SYSTEM SHALL merge configuration values, ensuring that project-level flags (`fetch_rates_on_generate`, `allowed_rate_sources`, `cache_ttl_days`) in the `.tproj` **override** the corresponding values in the `spectrac.tsln` or solution defaults.
**Acceptance Criteria:**
* The final, active configuration MUST be a single, merged object used for all subsequent operations.
* The `allowed_rate_sources` array must be correctly narrowed/overridden if present in the `.tproj`.

### R-P0-005: Standards File Registration (Non-Functional)
WHEN the Project Manifest is successfully loaded,
THE SYSTEM SHALL register the list of `standards_files` to be used by the NLP and generation engines.
**Acceptance Criteria:**
* The list of file paths (e.g., `../../../api-standards.md`) MUST be available to the generation logic for context injection.
